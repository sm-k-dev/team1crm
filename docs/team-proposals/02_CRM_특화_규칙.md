# CRM 프로젝트 특화 규칙

## 1. 매장별 데이터 격리
- [요구사항 기반] 고객·방문·포인트·쿠폰·분석은 로그인한 매장 범위 안에서만 조회·변경되어야 함.
- [제안] 클라이언트가 전달한 `storeId`만 신뢰하지 않고 인증된 사용자 소속 매장과 대조.
- [검증 필요] 다른 매장 고객 ID로 조회/수정/삭제/쿠폰 사용 요청 시 접근 차단 테스트.

## 2. 고객 개인정보
- [요구사항 기반] 고객 전화번호 마스킹, 끝 4자리 검색, 가짜 데이터 사용.
- [제안] 목록·로그·에러·AI 요청에 원문 전화번호가 노출되지 않는지 확인.
- [결정 필요] 고객 상세 화면에서 전화번호 표시 범위, 삭제 정책(강사 명세 우선), 동의 필드 처리 책임자.

## 3. 방문·매출·포인트
- [요구사항 기반] 방문/결제 기록, 포인트 적립·사용 내역.
- [제안] 금액·포인트 음수 및 잔액 초과 사용을 검증; 동일 요청 중복 제출 시 중복 기록 여부 확인.
- [결정 필요] 포인트 계산 반올림/절사 기준, 취소·정정 가능 범위(명세에 없으면 임의 기능 추가하지 않기).

## 4. 쿠폰
- [요구사항 기반] 발급·사용, 만료일·사용일 관리.
- [제안] 다른 매장 쿠폰 사용, 중복 사용, 만료 쿠폰 사용을 차단하는 테스트.
- [결정 필요] 쿠폰 할인 금액과 방문 결제의 관계(스타터 동작 먼저 확인).

## 5. 분석·RFM
- [요구사항 기반] 월별 매출, 요일·시간대 방문, 재방문율, 우수 고객, SQL NTILE(5) 기반 RFM.
- [제안] 집계 기간·시간대·빈 데이터·소수 고객 데이터의 처리 기준을 문서화하고 화면 표시와 SQL 결과를 비교.
- [결정 필요] R/F/M 점수 방향, 동점 처리, 고객 수가 5명 미만인 경우 표기 방식은 스타터 SQL 확인 후 결정.

## 6. AI 마케팅
- [요구사항 기반] RFM 집계 정보만 외부 AI로 전송; 개인 이름·전화번호 전송 금지; 무료 모델(`:free`), 1인 일 5회 제한, 입력 길이 제한, 텍스트 전용 출력.
- [제안] 무료 모델 장애·키 누락·요청 제한 초과 시 기능이 중단되지 않고 안내 문구 표시.
- [검증 필요] `th:text`/`textContent`를 통한 출력, XSS 페이로드 렌더링, 프롬프트에 개인정보 미포함.

## 7. 데모 데이터와 화면
- [요구사항 기반] 시드 2026 기반 가짜 고객 50명과 6개월 방문 예시. 실제 고객 데이터 사용 금지.
- [제안] 팀 공통 화면은 고객 검색·등록, 방문, 포인트, 쿠폰, 분석까지 같은 UI 원칙을 사용.
- [결정 필요] Modern SaaS 시안 채택 여부와 디자인 담당자/변경 범위.

## 8. CRM 최소 인수 테스트
1. 매장 A가 매장 B 고객·방문·쿠폰을 볼 수 없는가?
2. 고객 전화번호가 요구 화면에서 마스킹되는가?
3. 방문 등록 후 매출·포인트·분석 집계가 맞는가?
4. 포인트 잔액 초과, 쿠폰 중복 사용이 차단되는가?
5. AI 호출에 고객 개인식별정보가 포함되지 않는가?
6. AI 무료 모델·횟수 제한·오류 시 안내가 정상인가?
7. 빈 데이터·소수 고객·모바일 화면에서도 깨지지 않는가?


## v1 도메인 책임 (확정)
- `auth` 황현우: 회원/매장/로그인/보안. `customer` 김순민: 고객 CRUD/검색/마스킹.
- `loyalty.visit`, `loyalty.point`, `loyalty.coupon` 이재준: 방문·결제/포인트/쿠폰.
- `analytics` 한상희: 분석/RFM/AI. `home` 김순민: 홈/화면 통합. `infrastructure` 배수환: 인프라/배포/스토리지.
- AI 외부 전송에는 고객 이름/전화번호를 포함하지 않는다. 매장별 접근 격리를 유지한다.
