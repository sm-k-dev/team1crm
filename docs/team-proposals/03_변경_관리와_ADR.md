# 변경 관리 규칙 및 ADR

## 변경 분류 [제안]
- **일반 변경**: 자신의 화면 CSS, 오타, 독립적인 테스트. 기존 계약을 바꾸지 않는 범위에서는 PR 리뷰로 처리.
- **공통 영향 변경**: 인증/세션/JWT, PasswordEncoder, 엔티티/스키마, API 계약, 공통 레이아웃, 공통 설정, CI/CD, 의존성. 작업 전 담당자와 영향 범위 공유 후 팀 합의.
- **강사 요구 변경**: 기능 제외·기술 스택 변경·평가 조건 변경. 팀 합의만으로 변경하지 않고 강사 확인 필요.

## 제안 → 결정 → 구현 → 검증
1. GitHub Issue에 문제·변경 목적·대안·영향받는 파일/팀원·위험·롤백 방법 기록.
2. 스타터 요구와 충돌하는지 확인; 필요한 경우 강사 확인.
3. `04_합의_결정_기록.md`에 승인/보류/반려 및 근거 기록.
4. 승인된 변경만 별도 feature 브랜치에서 작업; PR 본문에 결정 ID 기재.
5. 리뷰·CI·통합 테스트 후 develop에 병합; 필요시 main 배포 검증.

## 변경 후보 예시 (승인 아님)
- ADR-001: Modern SaaS UI 디자인 적용 — HTML/CSS만 변경하는 방향, 실제 기능 회귀 테스트 필요.
- ADR-002: BCrypt → Argon2id — 현재 스타터 `PasswordEncoderConfig`와 `DataInitializer`가 BCrypt에 의존. 알고리즘 변경만 하면 기존 해시 인식·로그인이 깨질 수 있음. 팀 승인 전 미적용.


## v1 패키지 변경 승인 기준
- `auth` 황현우, `customer` 김순민, `loyalty` 이재준, `analytics` 한상희, `home` 김순민, `infrastructure` 배수환이 기본 리뷰 담당이다.
- 패키지 이동·공용 DTO·보안·DB·Thymeleaf fragments·공통 스타일 변경은 영향 도메인 담당자에게 PR 리뷰를 요청한다.
- 변경 시 컴파일/테스트 결과와 API/템플릿 경로 영향, 롤백 방법을 PR에 기록한다. 상세: `../architecture/02_도메인_간_연동_규칙.md`.
