# 한국어 Comment · 작성자 · 작성일 · 변경 기록 (작성일, 변경사항 - 누적)

**목표:** 학습 중인 팀원이 다른 사람의 코드를 빠르게 이해하도록 한다. 아래는 사용자 제안을 반영한 **팀 검토용 규칙**이며, 아직 팀 전체 승인 전이다.

## 기본 규칙 제안
1. **한국어**로 간결하고 구체적인 주석을 작성한다.
2. 개발자가 직접 작성하는 **모든 클래스·인터페이스·Enum·생성자·메서드**(public/protected/package-private/private 포함)에 역할을 적는다.
3. 클래스와 메서드의 **최초 작성자 및 최초 작성일**을 기록한다. 날짜 형식은 `YYYY-MM-DD`로 통일한다.
4. 메서드의 입력/반환/예외가 이해하기 어려울 때 `파라미터`, `return`, `throws`를 추가한다.
5. 업무 규칙·권한 확인·부작용·트랜잭션 등 중요한 제약은 짧게 명시한다.
6. **중요한 동작 변경** 시에만 변경 일자·담당자·한 줄 이유를 덧붙이고, 기존 설명을 현재 동작에 맞춰 갱신한다. 단순 포맷·오타·이름 변경은 Git 이력으로 확인한다.
7. 코드와 주석이 어긋나면 주석도 함께 수정한다. 주석은 코드의 진실을 대체하지 않는다.
8. Lombok·프레임워크 자동 생성 메서드는 제외. 단순 getter/setter·테스트 메서드의 예외 허용 여부는 팀에서 결정한다.
9. 기존 스타터 코드를 주석만 달기 위해 일괄 변경하지 않는다. 새로 작성하거나 실질적으로 수정하는 부분부터 적용한다.
10. 작성자 이름은 팀에서 합의한 **GitHub ID 또는 표시명** 중 하나를 일관되게 사용한다. 작성일은 로컬 개발 시작일 기준인지 최초 커밋일 기준인지 합의한다.

## 예시 (설명용; 스타터 소스 변경 아님)
```java
/**
 * 현재 매장의 고객을 조회하고 매장 소유권을 확인하는 서비스이다.
 *
 * 작성자 team-member-a
 * 작성일 2026-11-05
 */
@Service
public class CustomerService {

    /**
     * 현재 매장에 속한 고객을 조회한다.
     * 다른 매장의 고객이면 조회를 허용하지 않는다.
     *
     * 파라미터 customerId 조회할 고객 ID
     * return 현재 매장 소속 고객
     * 작성자 team-member-a
     * 작성일 2026-11-05
     */
    public Customer findCustomer(Long customerId) {
        // 기존 스타터의 매장 소유권 검증 로직 사용
        throw new UnsupportedOperationException("설명용 예시");
    }
}
```

## 중요한 변경 이력 예시
```java
/**
 * 방문 금액을 기준으로 포인트를 적립한다.
 *
 * 작성자 team-member-c
 * 작성일 2026-11-06
 * 변경노트 2026-11-10 team-member-b: 중복 적립 방지 조건 추가 (PR #예시)
 */
```

## 파일 버전과의 구분
- 주석의 작성자·최초 작성일·중요한 변경 설명은 **코드 이해를 위한 주석**이다. 실제 버전·수정 이력은 Git Commit·PR이 기준이다.
- 소스코드 파일명에 날짜나 `v1`, `v2`를 붙이지 않는다. 문서 산출물의 버전 규칙은 `../docs/01_문서_네이밍_버전관리_규칙_초안.md`를 참조한다.

## 날짜·이름 기록의 한계
- `작성자`와 `작성일`는 **최초 작성 정보** GitLog추적을 위해 작성한다.
- 누가 언제 정확히 어느 줄을 바꿨는지는 **Git blame / Git log / PR**이 최종 근거다.
- 주석에는 개인 연락처 등 개인정보를 적지 않는다.

## 팀 결정 필요
- [ ] 클래스와 메서드 모두 `작성자`, `작성일` 필수
- [ ] 최초 작성일 기준: 개발일 / 최초 커밋일
- [ ] 중요한 변경의 정의와 변경 기록 위치: 주석 한 줄
- [ ] 단순 getter/setter·테스트·생성자 예외
