2026-11-26 검증일지의 김순민 담당 미완료 9건을 점검했다. 7건은 확인한 범위에서 완료, 2건은 남은 확인을 명시해 개선 중으로 유지한다. 해당 코드 보완은 `9ea54dd1d64d8af79e3542ae53a5ccc30340af96`로 커밋됐고 11/27 main `67f778b`의 CI/CD 성공을 확인했다. 이 보고서 자체의 Git 반영과 코드 배포는 구분한다.

## 실행 결과

- JDK 25, Spring Boot 4.0.0, 실제 MySQL 8.0의 폐기용 `crm_validation` DB에서 prod 프로필과 실제 Spring Security 필터를 적용했다.
- 전체 테스트 243건 실행, 실패 0, 오류 0, 건너뜀 0. MySQL 통합 검증 7건 포함.
- 실행 JAR 생성 성공. 로컬 검증 서버는 prod의 `ddl-auto=validate`로 기동 성공했다. 평소 개발 포트 8082와 분리한 18082를 사용했다.
- 운영 DB는 Workbench의 `information_schema.COLUMNS` SELECT만 실행했다. DDL·업무 데이터 변경은 하지 않았다.

## 재현

신규 검증 클래스: `src/test/java/com/team1/crm/verification/ProdMysqlVerificationTest.java`.
기존 customer, StoreClosureTest, StoreManagementLayoutTest, FakeDataInitializerTest와 함께 실행했다.

검증 클래스는 `CRM_MYSQL_VERIFICATION=true`일 때만 실행한다. 운영 DB로 테스트 URL을 변경하지 않는다. 이 테스트는 하드코딩한 로컬 전용 포트 33316과 폐기용 DB만 사용하며 스키마를 생성한다. 실제 서버와 공유 DB에 적용하는 테스트가 아니다.

```powershell
$env:CRM_MYSQL_VERIFICATION='true'
.\gradlew.bat test --no-daemon
```

기본 CI 실행에서는 MySQL 검증 7건이 건너뛰어지므로, 이번 243건 전체 실행 결과와 CI의 기본 실행 범위를 구분한다.

## 원격 DB 확인 쿼리

```sql
SELECT TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'matzip'
  AND ((TABLE_NAME = 'customer' AND COLUMN_NAME IN ('deleted_at','anonymized_at','phone'))
    OR (TABLE_NAME = 'store' AND COLUMN_NAME = 'closed_at'))
ORDER BY TABLE_NAME, COLUMN_NAME;
```
