1. 전체 구성 (3개 주제 공통)

팀원 PR→CI: 빌드·테스트→develop 머지→develop → main→CD: jar 를 S3 deploy/ 업로드→EC2 가 S3 에서 받아 재시작→접속 확인
구분공통 내용
CIGitHub Actions ci.yml : PR 마다 ./gradlew clean build. 테스트는 H2(MySQL 모드)라 DB 없이 실행
CDGitHub Actions cd.yml : main 머지 → S3 deploy/ → EC2 java -jar 재시작 → curl 확인
서버EC2 1대 (Ubuntu 24.04, t3.micro, 20GB) + systemd 서비스
DBEC2 안의 MySQL 8 (3306 포트는 외부에 열지 않음)
파일S3 images/ (사진), 버킷 비공개, 앱이 /api/files/{이름} 으로 제공
권한EC2 = IAM 역할(키 없음) / GitHub = 업로드 전용 IAM 사용자
주제가 달라도 바꾸는 것은 이름 3개(서비스 이름, S3 버킷 이름, DB 이름)뿐입니다. 아래 2번 표를 보세요.

6. EC2 서버 준비 (Day 6)

EC2 터미널
# 0. 내 PC 에서 EC2 접속 (Windows PowerShell 또는 WSL)
ssh -i matzip-key.pem ubuntu@탄력적IP

# 1. Java 21, AWS CLI
sudo apt update
sudo apt install -y openjdk-21-jre-headless curl unzip
sudo snap install aws-cli --classic

# 2. 스왑 2GB (메모리 1GB 서버에서 MySQL + 스프링 동시 실행)
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 3. 폴더 만들고 deploy 파일 올리기 (내 PC 에서 실행)
#    scp -i matzip-key.pem deploy/* ubuntu@탄력적IP:/home/ubuntu/matzip/
mkdir -p /home/ubuntu/matzip && cd /home/ubuntu/matzip

# 4. MySQL 8 설치 + DB·계정
bash mysql-setup.sh '여기에_DB_비밀번호'

# 5. 환경 변수
cp matzip.env.example matzip.env && nano matzip.env && chmod 600 matzip.env

# 6. 서비스 등록
sudo cp matzip.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable matzip

# 7. S3 권한 확인 (IAM 역할이 연결됐으면 키 없이 성공)
aws s3 ls s3://matzip-팀번호-2026
deploy/mysql-setup.sh
#!/bin/bash
# ============================================================
# [mysql-setup.sh] EC2(Ubuntu 24.04)에 MySQL 8 설치 + matzip DB·계정 생성 (부팀장, 1회 실행)
# 사용법: bash mysql-setup.sh '여기에_DB_비밀번호'
# 실행 후 /home/ubuntu/matzip/matzip.env 의 DB_PASSWORD 에 같은 비밀번호를 넣는다.
# ============================================================
set -e
DB_PASSWORD="$1"
if [ -z "$DB_PASSWORD" ]; then
  echo "사용법: bash mysql-setup.sh 'DB비밀번호'"; exit 1
fi

# 1. MySQL 8 설치 (Ubuntu 24.04 기본 저장소는 MySQL 8.0)
sudo apt update
sudo apt install -y mysql-server
sudo systemctl enable --now mysql

# 2. 외부 접속 차단 확인: 앱과 DB 가 같은 서버이므로 127.0.0.1 에서만 받는다 (기본값 유지)
#    보안 그룹에 3306 포트를 열지 않는다.
grep -E "^bind-address" /etc/mysql/mysql.conf.d/mysqld.cnf || true

# 3. DB 와 전용 계정 만들기 (utf8mb4: 한글·이모지 저장)
sudo mysql <<SQL
CREATE DATABASE IF NOT EXISTS matzip DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'matzip'@'localhost' IDENTIFIED BY '${DB_PASSWORD}';
GRANT ALL PRIVILEGES ON matzip.* TO 'matzip'@'localhost';
FLUSH PRIVILEGES;
SQL

# 4. 확인
mysql -u matzip -p"${DB_PASSWORD}" -e "SELECT VERSION(); SHOW DATABASES LIKE 'matzip';"
echo "MySQL 준비 완료. matzip.env 에 DB_PASSWORD 를 넣고 sudo systemctl restart matzip"
deploy/matzip.env.example
# EC2 의 /home/ubuntu/matzip/matzip.env 로 복사한 뒤 값을 채우고 chmod 600 으로 보호한다.
# 실제 값이 든 파일은 절대 GitHub 에 올리지 않는다 (.gitignore 의 *.env 로 제외됨).

# ── 로그인 토큰 ──

# ── AI (OpenRouter 무료 모델만) ──

브랜치 보호 (Settings → Branches)

  3. Require status checks to pass → build
.github/workflows/ci.yml
name: CI Build & Test

# 실행 조건: develop, main 으로 PR 을 올리거나 push 할 때
on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  build:
    runs-on: ubuntu-latest          # GitHub 이 빌려주는 리눅스 컴퓨터에서 실행

    steps:
      - name: 코드 내려받기
        uses: actions/checkout@v4

      - name: JDK 21 설치 + Gradle 캐시
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: 'gradle'

      - name: 빌드 + 테스트
        # AI 키는 넣지 않는다. application.properties 의 기본값(no-key)으로 서버가 켜지는지만 확인한다.
        # 테스트가 하나라도 실패하면 빨간불 → 브랜치 보호 규칙에 의해 머지가 막힌다.
        run: |
          chmod +x gradlew
          ./gradlew clean build

      - name: 테스트 결과 보관 (실패해도 업로드)
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-report
          path: build/reports/tests/test/
          retention-days: 7
.github/workflows/cd.yml
name: CD Deploy to EC2 via S3

# 실행 조건: main 에 머지(push)될 때, 또는 Actions 화면에서 Run workflow 로 직접 실행할 때
on:
  push:
    branches: [ main ]
  workflow_dispatch:

# 배포가 두 개 동시에 돌지 않게 막음
concurrency:
  group: deploy-main
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - name: 코드 내려받기
        uses: actions/checkout@v4

      - name: JDK 21 설치 + Gradle 캐시
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: 'gradle'

      - name: 빌드 (테스트 포함)
        run: |
          chmod +x gradlew
          ./gradlew clean build

      - name: 배포 파일 준비
        run: |
          mkdir -p deploy-out
          # build.gradle 의 bootJar 설정으로 build/libs/my-matzip.jar 하나만 만들어진다
          cp build/libs/my-matzip.jar deploy-out/my-matzip.jar

      - name: AWS 로그인 (GitHub용 IAM 사용자)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ${{ secrets.AWS_REGION }}

      - name: S3 에 배포 파일 업로드
        run: aws s3 cp deploy-out/my-matzip.jar s3://${{ secrets.S3_BUCKET }}/deploy/my-matzip.jar

      - name: EC2 에서 내려받고 재시작 + 접속 확인
        uses: appleboy/ssh-action@v1.0.3
        env:
          S3_BUCKET: ${{ secrets.S3_BUCKET }}
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ubuntu
          key: ${{ secrets.EC2_SSH_KEY }}
          envs: S3_BUCKET
          script: |
            aws s3 cp s3://$S3_BUCKET/deploy/my-matzip.jar /home/ubuntu/matzip/my-matzip.jar
            sudo systemctl restart matzip
            for i in $(seq 1 40); do
              if curl -sf http://localhost:8082/ > /dev/null; then
                echo "배포 성공"
                exit 0
              fi
              sleep 3
            done
            echo "배포 실패: 최근 로그"
            sudo journalctl -u matzip -n 60 --no-pager
            exit 1

8. 배포 실패할 때 확인 순서

증상 (Actions 로그)원인해결
빌드 단계 실패테스트 실패, 컴파일 오류CI 와 같은 원인. 해당 PR 작성자가 수정
AWS 로그인 단계 실패액세스 키 오타, 리전 오타Secrets 다시 입력
S3 업로드 AccessDeniedIAM 사용자 정책의 버킷 이름 오타정책 Resource 의 버킷 이름 확인
SSH 단계 timeout보안 그룹 22 닫힘, EC2 꺼짐, EC2_HOST 오타보안 그룹·탄력적 IP 확인
SSH 단계 permission deniedEC2_SSH_KEY 일부만 복사.pem 전체 다시 붙여 넣기
EC2 의 aws s3 cp 실패EC2 에 IAM 역할 미연결EC2 → 작업 → 보안 → IAM 역할 수정
"배포 실패: 최근 로그" + DB 오류matzip.env 의 DB_PASSWORD 틀림, MySQL 꺼짐sudo systemctl status mysql, env 확인
