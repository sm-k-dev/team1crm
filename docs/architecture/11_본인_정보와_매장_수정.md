# 내 정보·내 매장 수정

작성자: 김순민 / 작성일: 2026-11-12

## 화면과 범위
- 로그인 이름 링크에서 `/my-profile`로 이동한다. 이메일은 조회만 하고 본인 이름을 수정한다. 본인 ID는 LoginMember에서 가져오며 다른 회원 ID를 폼으로 받지 않는다.
- 이름은 공백 금지·255자 이하, 앞뒤 공백 제거 후 다른 계정과 중복 검사한다. 자기 현재 이름은 허용한다. 이메일·비밀번호·역할·소유 매장은 변경하지 않는다.
- 이메일 변경·인증과 비밀번호 변경·재설정은 현우 담당 공통 인증 정책에 연동할 후속 범위이다.
- 내 매장 정보의 영업 매장 카드에서 `/stores/{storeId}/edit`로 이동한다. 매장명·업종·주소·적립률을 수정하고 소유자 변경은 제공하지 않는다.
- 매장명 필수·50자, 업종 30자, 주소 200자 이하이다. 적립률은 현재 사장님 등록 기능과 같은 0~20%이다. 기존 ADMIN 폼의 0~100%와 차이가 있으므로 공통 정책 통일은 후속 협의 대상이다.
- 같은 사장님의 다른 영업 매장 이름 중복은 거절하고, 다른 사장님의 같은 매장명 및 폐업 매장명 재사용은 허용한다. 자기 현재 이름은 허용한다. 기존 사장님 등록 처리에도 같은 사전 검사를 적용한다.
- 매장 이름의 검사 범위는 앱의 사전 검사이다. 별도의 DB 유니크 제약을 추가하지 않았으며 동시 등록까지 완전 차단했다고 보장하지 않는다. ADMIN 경로의 이름 중복 정책 통일도 후속이다.
- 잠금 후 소유자·폐업을 확인하여 저장한다. 다른 사장님의 매장은 403, 폐업 매장 수정은 409이다. 오류 시 입력값·필드 오류를 유지하고 성공하면 리다이렉트한다.

## 폐업 분석 안내 수정
- 매출·방문 기록이 있어도 폐업으로 고객 주요 정보를 제거하면 RFM 대상은 없을 수 있다.
- 고객 등급 카드와 표에 폐업 매장은 고객 등급 분석을 제공하지 않는다고 표시한다.
- 영업 매장에서도 RFM 결과가 없으면 방문 자체가 없다고 단정하지 않고 등급 분석 대상 고객이 없다고 안내한다.

## 검증
- H2에서 본인 이름 수정·중복 거절·인증 필드 보존, 매장 소유 범위 중복·타 소유자 동명 허용·소유 관계 유지·폐업/타 매장 차단 및 실제 폼 렌더링을 검증한다.
- 기존 매장 폐업 테스트에 분석 화면의 폐업 RFM 안내 렌더링을 추가했다.
- 실제 MySQL의 내 정보·매장 수정 화면, 중복 오류 및 재로그인은 후속 확인 대상이다. 새 DB 컬럼이나 라이브러리는 필요하지 않다.

## 실제 화면 검증 및 메뉴 정리 (2026-11-12)
- 계정 900006의 내 정보 화면에서 카페사장 이름 중복 안내와 입력 유지 후, 내정보수정확인용으로 정상 저장·상단 이름 갱신을 확인했다. 로그인 이메일과 소유 매장은 유지됐다.
- 사장님이 매장 900107의 이름을 사장님수정확인용, 주소를 매장 수정 테스트 주소, 적립률을12%로 저장한 뒤 같은 ID로 표시됨을 확인했다. 폐업 매장 900108에는 수정 버튼이 없었다.
- 다른 영업 매장 이름인 중복검증용매장으로 변경 시 필드 오류·입력 유지가 표시됐고, 취소 후 900107의 기존 이름·주소·12%가 그대로임을 확인했다.
- 매장 등록은 홈에서 내 매장 정보의 등록 영역으로 이동했다. 기존 API·중복 검사·CSRF 헤더 처리를 재사용하고 등록 JS는 store-registration.js로 옮겼다. 홈은 운영 요약과 고객 관리·매장 관리·분석 이동 버튼을 제공한다. 매장 미보유 안내도 내 매장 정보 등록 영역으로 이동한다.
- 내 매장 정보는 영업 중인 매장 ID 오름차순 다음 폐업한 매장 ID 오름차순으로 표시하고 구역 제목을 나눈다.
- 사장님 내비게이션은 현황·분석(운영 현황/분석·RFM·AI)과 매장·고객 관리(내 매장 정보/고객 관리)로 구분한다. ADMIN 메뉴는 유지한다.
- 위치 이동 후 실제 브라우저의 등록 요청과 CSRF 검증은 후속 확인 대상이다. 자동 테스트는 폼 위치·토큰 메타·스크립트 연결·안내 링크·목록 정렬·화면 구역을 확인한다.
