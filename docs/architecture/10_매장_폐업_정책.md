# 매장 폐업 및 읽기 전용 조회

작성자: 김순민 / 작성일: 2026-11-11

## 결정한 동작
- 사장님은 내 매장 정보에서 본인 소유 매장을 폐업 처리한다. 매장명은 바꾸지 않고 closed_at으로 상태를 표시한다. NULL은 영업 중, 값이 있으면 폐업이다.
- 매장·고객·방문·포인트·쿠폰 행과 소유 관계는 삭제하지 않는다. 과거 매출·방문·고유 방문 고객 수를 유지한다.
- 폐업은 일반 고객 삭제의 3개월 보관과 구분한다. 폐업 시 해당 매장의 모든 고객 이름을 삭제된 고객으로 대체하고 전화번호·생일·메모를 NULL, 수신 동의를 false로 즉시 변경한다. 삭제 시각과 주요 정보 제거 완료 시각을 기록한다. 이미 있던 최초 시각은 보존한다.
- 개인정보가 복사될 수 있는 방문 메모는 NULL, 쿠폰 제목은 폐업 매장 쿠폰으로 대체한다. 결제 금액·방문일·포인트·할인액·사용 이력은 유지한다. 다른 매장 고객은 변경하지 않는다.
- 로그·백업·이미지·기존 내보내기 파일까지 제거했다고 보장하지 않는다. 별도 저장처의 개인정보 정리는 후속 점검이다. 고객 ID와 거래가 남으므로 완전 익명화라고 표현하지 않는다.
- 정보 제거는 복구할 수 없으므로 화면에 확인 문구를 표시한다. 복구·재개업 기능은 제공하지 않는다. 재등록은 새 매장으로 처리한다.

## 접근과 연동
- POST `/stores/{storeId}/close`는 로그인한 USER 사장님만 허용하고 Service에서 소유권을 다시 검사한다. 다른 사장님은 403이다.
- 폐업 시각·고객 정보 제거·자유입력 정리를 단일 트랜잭션으로 묶는다. 이미 폐업했으면 최초 시각을 유지하고 반복 처리하지 않는다.
- 폐업과 고객 등록·수정·삭제, ADMIN 매장 수정은 같은 매장에 PESSIMISTIC_WRITE 잠금을 사용한다. 고객 쓰기 및 ADMIN 수정은 최신 DB 폐업 여부도 확인한다. 실제 MySQL 동시성 부하 검증을 완료한 것은 아니다.
- 폐업 매장은 내 매장 정보·홈·분석의 소유 목록에 남는다. 상태를 폐업으로 표시하고 과거 통계를 조회한다. ADMIN도 상태를 확인하지만 매장 정보 수정·소유자 변경은 차단한다.
- 고객 관리의 영업 매장 목록에서는 폐업 매장을 제외한다. 연결 매장이 없으면 HTTP 200 안내 화면, 전부 폐업했거나 폐업 매장을 선택하면 읽기 전용 설명과 과거 통계 링크를 제공한다. 임의로 다른 영업 매장을 요청하면 기존 소유권 검사를 유지한다.
- 폐업 매장의 AI 마케팅 문구 생성은 거절한다. RFM은 제거된 고객의 deleted_at 조건으로 제외되고 과거 매출·방문 집계는 유지된다.
- 현재 브랜치의 VisitService·CouponService는 미구현 틀이다. C 담당이 신규 거래를 연결할 때 같은 매장 잠금 및 폐업 차단과 삭제 고객 거절을 반드시 적용해야 한다. 기존 CustomerService.findCustomer만 사용하면 폐업 직후에는 고객이 이미 삭제 상태지만 동시 거래의 원자성까지 보장하지 않는다.

## 마이그레이션 및 검증
- [store_closure_migration.sql](../sql/store_closure_migration.sql)을 확인하고 운영 DB에는 closed_at을 사전에 적용한다. 고객 phone NULL 허용과 deleted_at·anonymized_at도 필요하다. 실제 DB에는 이 작업에서 직접 적용하지 않았다.
- 자동 테스트로 매장명·관계·금액 보존, 고객/방문 메모/쿠폰 제목 제거, 타 매장 격리, 재처리 제외, 소유권 및 쓰기 거절을 확인한다.
- 실제 MySQL과 브라우저 폐업 실행·통계 대조·CSRF와 동시 거래는 후속 검증 대상이다. 테스트할 때는 기록 보존을 확인할 폐기 가능한 테스트 매장을 사용한다.

## 로컬 수동 검증 (2026-11-12)
- 사용자 실행·공유 화면 기준. 테스트 매장 900108(폐업검증용), 소유자 900006, 고객 900234를 사용했다.
- closed_at DATETIME(6) NULL 컬럼 생성 확인 후, 고객의 생일11월·메모·수신 동의 및 11/10 10,000원·11/11 20,000원 방문을 준비했다.
- 폐업 후 매장명 폐업검증용·ID·소유 관계가 유지되고 closed_at에 2026-11-12 09:09:50.114357 기록을 확인했다. 고객은 삭제된 고객으로 대체, phone·birth_month·memo=NULL, 동의0, deleted_at·anonymized_at 기록을 확인했다.
- 폐업 전과 후 SQL 집계에서 방문2건·매출30,000원·고유 방문고객1명이 동일했고, 메모 있는 방문 수만2→0으로 변경됐다.
- 고객 관리 URL은 오류 대신 폐업 읽기 전용 안내와 과거 통계 링크를 표시했다. 링크로 이동한 2026년11월 분석 화면에서도30,000원·2건·1명·기간 내 재방문율100%를 확인했다.
- 고객 등급의 기존 방문 기록 없음 문구가 부정확함을 발견해 별도 폐업 안내로 수정했다. 포인트·쿠폰 실제 MySQL 보존, 전체 CSRF·동시 거래 검증은 이번 수동 검증에 포함하지 않았다.
