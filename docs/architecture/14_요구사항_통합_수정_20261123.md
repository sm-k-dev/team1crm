# 요구사항 통합 수정 — 2026-11-23

작성자: 김순민. 현재 구현 기준이며, 초기 기획의 목표 API와 구분한다.

## 운영 화면

홈·고객·관리자·분석·방문/쿠폰 화면은 dev와 prod 모두에서 제공한다.
인증·매장 소유권·CSRF 검사는 기존 SecurityConfig를 그대로 적용한다.
prod는 실제 DB의 스키마가 일치해야 하며, /login HTTP 200만으로 업무 기능 검증이 끝나지 않는다.

## 매장 입력 및 오류

매장 이름 1~50자(공백만 불가), 업종 최대 30자, 주소 최대 200자, 적립률 0~20%.
이름·주소는 앞뒤 공백을 제거한 동일한 값으로 중복 검사와 저장을 수행한다.
없는 매장 404, 다른 소유자의 매장 403, 타 매장/삭제/없는 고객 404.
잔액 부족 등 업무 검증 오류는 400, 폐업 매장 변경은 409.

## 시연 데이터

`FakeDataInitializer`가 dev 프로필 + `CRM_DEMO_ENABLED=true`인 경우에만 생성한다.
`CRM_DEMO_PASSWORD`는 8~20자, 영문·숫자·특수문자를 포함하며 공백을 허용하지 않는다.
비밀번호는 실제 PasswordEncoder로 해시한다. 고정 비밀번호나 실제 개인정보는 저장소에 넣지 않는다.

- 관리자: `admin.demo@crm.local`
- 사장님: `owner.demo@crm.local` (매장 2개)
- 가상 고객 50명, 현재 월 포함 6개월 방문/결제/적립 내역
- 일부 고객은 최근 2개월 미방문으로 이탈 위험 시연에 사용
- 사장님 전용 이메일이 이미 있으면 생성을 건너뛰며 기존 데이터를 변경하지 않는다.
- 관리자 전용 이메일만 이미 존재하면 충돌로 중단한다. 생성 전체는 단일 트랜잭션이다.

개발 환경 변수에 두 값을 설정하고 앱을 한 번 실행한 뒤 `CRM_DEMO_ENABLED=false`로 되돌린다.
prod에서는 플래그를 켜도 생성기를 등록하지 않는다. 과거 seed_dummy.sql 데이터는 자동 정리하거나 덮어쓰지 않는다.

## RFM

- 기준 시각: 선택 월 말. 다음 달 이후 방문은 제외한다.
- 대상: 해당 시점까지 한 번이라도 방문한 현재 고객. 삭제 고객은 제외한다.
- R: 기준 시각 이전 전체 방문 중 마지막 방문일.
- F/M: 선택 월을 포함한 최근 6개월의 방문 수/실결제 금액. 해당 기간 미방문이면 0.
- 마지막 방문 후 60일 이상이면 이탈 위험을 우선 적용한다.
- 그 외 고객은 기존 NTILE 점수와 VIP/단골/일반/이탈 위험 분류를 유지한다.
- 방문 이력이 전혀 없는 신규 고객은 RFM에서 제외한다.

월간 매출·재방문율 집계 기간은 기존처럼 선택 월이며 RFM의 6개월 기간과 구분한다.

## 범위 및 연동 규칙

승인·반려·정지·재활성화는 현재 개발 범위에서 제외한다. 사장님 역할의 실제 enum 값은 USER다.
초기 기획서의 상태 전이와 OWNER enum 마이그레이션은 현재 필수 미구현 항목으로 계산하지 않는다.
CSV는 선택 기능이다. 포인트·쿠폰 사용은 별도 API 대신 방문 등록 트랜잭션에 통합한다.
AI는 집계만 전송하고 매장별 하루 5회 제한을 사용한다. 현재 제한은 메모리 방식이므로 재기동 시 초기화된다.
개인정보 자동 파기는 스키마 확인 후 CUSTOMER_PRIVACY_ENABLED로 별도 활성화한다.

다른 도메인의 Repository 직접 참조는 단계적으로 Service 계약으로 이동한다.
현재 관리자 계정/매장 생성 및 고객 쓰기 잠금의 기존 직접 참조는 남아 있으며, 전체 해소됐다고 간주하지 않는다.
