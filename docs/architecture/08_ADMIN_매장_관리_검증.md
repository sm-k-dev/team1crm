# ADMIN 매장 관리 구현 및 로컬 검증 기록

작성자: 김순민 / 검증일: 2026-11-11

기록 근거: 사용자 실행 결과와 공유한 브라우저·MySQL Workbench·오류 로그.

## 구현 범위

- ADMIN의 전체 매장 조회, 매장 등록·수정, 기존 사장님 연결 및 소유자 변경.
- 매장명·업종·주소·적립률 표시 및 입력 검증, 성공 시 목록으로 리다이렉트, 오류 시 입력값 유지.
- 현 구현에서 사장님 역할은 USER이다. ADMIN 및 존재하지 않는 회원을 매장 소유자로 지정하지 않는다.
- 사장님 한 명이 여러 매장을 소유할 수 있다. 연결된 사장님 수는 회원 ID의 중복을 제거해서 센다.
- 승인·반려·정지 상태 관리와 신규 사장님 계정 생성은 이번 구현 범위가 아니다.

## 기존 DB 유니크 제약으로 인한 등록 실패

### 증상과 원인

기존 사장님에게 두 번째 매장을 등록할 때 오류 화면이 표시됐다. 실행 로그에서 MySQL 오류 1062, SQLState 23000 및 아래 메시지를 확인했다.

```text
Duplicate entry '900003' for key 'store.UK2a7h1b2fiymx7vm90mlj2im1q'
```

`SHOW INDEX` 결과 해당 인덱스는 member_id 단일 컬럼에 대한 유니크 인덱스(Non_unique=0)였다. Java의 Store.owner는 ManyToOne으로 변경되어 있었지만, 기존 DB에는 한 회원당 매장을 하나로 제한하는 제약이 남아 있었다. 개발 환경의 ddl-auto=update만으로 기존 유니크 제약 제거까지 보장되지 않음을 확인했다.

### 적용한 조치

외래키 지원용 일반 인덱스를 먼저 추가한 뒤, 확인된 기존 유니크 인덱스만 제거했다.

```sql
CREATE INDEX idx_store_owner ON crm.store (member_id);

ALTER TABLE crm.store
DROP INDEX UK2a7h1b2fiymx7vm90mlj2im1q;
```

이 SQL은 해당 로컬 DB에서 적용한 기록이다. 팀원·배포 DB에서는 인덱스 이름과 기존 일반 인덱스 존재 여부가 다를 수 있으므로 그대로 일괄 실행하지 않는다. [수동 마이그레이션 안내](../sql/store_multi_owner_migration.sql)에 따라 현재 정의를 확인하고 필요한 문장만 실행한다. 적용 후 전체 인덱스 및 외래키 정의도 확인한다.

## 실제 브라우저·MySQL 검증 결과

테스트 매장 ID: 900107. 기존 매장 3개와 연결된 사장님 3명이 있는 상태에서 시작했다.

| 검증 항목 | 실제 결과 |
| --- | --- |
| ADMIN 전체 매장 조회 | 기존 매장 3개의 매장·사장님·이메일 표시 |
| 기존 식당사장에게 테스트 매장 추가 | 등록 성공, 전체 매장 4 / 연결된 매장 4 / 연결된 사장님 3 |
| 적립률 수정 | 같은 ID 900107에서 5% → 10% 변경 |
| 매장명 수정 | 관리자등록확인용 → 관리자수정확인용 변경 |
| 수정 후 집계 | 4 / 4 / 3 유지, 새 매장 행이 추가되지 않음 |
| 소유자 변경 | 식당사장 → 카페사장, 연결 이메일도 새 소유자 이메일로 표시 |
| 새 소유자의 내 매장 정보 | 기존 매장 900101과 변경된 매장 900107이 함께 표시 |
| 새 소유자의 고객 관리 접근 | /customers?storeId=900107 정상 표시, 고객 0명 |
| 이전 소유자의 같은 URL 직접 접근 | 오류 화면 표시, Network의 document 요청 HTTP 403 확인 |

따라서 소유자 변경이 목록 표시뿐 아니라 해당 고객 관리 GET 요청의 서버 소유권 검사에도 반영됨을 확인했다. 모든 API·POST 요청의 권한 검증 완료로 확대 해석하지 않는다.

## 자동 테스트와 남은 확인

- 등록·수정 구현 후 전체 테스트 110건 통과(실패·오류 0). 관리자 테스트는 10건이다.
- H2에서 전체 매장 조회·계정 중복 집계 방지·등록·변경 감지 수정·잘못된 소유자 거절·입력 오류 시 기존 값 유지·404 및 실제 Thymeleaf 출력을 검증했다.
- Controller 권한 분기를 검사했으며 자동 테스트가 실제 보안 필터 전체를 실행한 것은 아니다. 위 브라우저 검증은 실제 로그인 상태의 특정 접근 사례를 보완한다.
- 실제 브라우저에서 입력 오류 메시지·기존 입력 유지, ADMIN 화면·POST의 비관리자 차단, 운영 프로필 화면 및 배포 DB 마이그레이션은 후속 확인 대상이다.
- 테스트 매장 900107은 검증 후 삭제하지 않았으며 최종 확인된 소유자는 카페사장이다.
