# 개발/운영 환경 및 DB 정책

**현재 Starter는 MySQL(DataSource/JPA)과 Thymeleaf가 활성화되어 있습니다.** 기본 프로필은 `dev`이며, `dev`와 `prod` 모두 접속 가능한 MySQL이 필요하고 `spring.thymeleaf.enabled=true`로 설정되어 있습니다. Thymeleaf 캐시는 개발에서 비활성화, 운영에서 활성화됩니다. 업무 기능과 운영용 인증/인가는 별도 구현이 필요합니다.

기술 기준: **JDK 25, Spring Boot 4.0.0, Gradle 9.2.1, MySQL 8**.

## DB 연결형 로컬 개발(dev)
1. MySQL에 `crm` 데이터베이스와 개발 전용 사용자를 생성합니다.
2. `SPRING_PROFILES_ACTIVE=dev`, `SERVER_PORT`(예: `8082`), `DB_USERNAME`, `DB_PASSWORD`를 실행 환경변수로 지정합니다. URL이 다르면 `DB_URL`을 지정합니다. `.env` 파일은 자동으로 로드되지 않으므로 IDE 또는 운영체제 환경변수로 주입합니다.
3. Windows PowerShell에서 `.\gradlew.bat bootRun`을 실행하거나 IntelliJ에서 `CrmApplication`을 실행합니다. 프로필은 환경변수 한 곳에서 지정합니다.
4. `ddl-auto=update`: 기존 데이터를 지우지는 않지만 스키마 변경을 안전하게 보장하지 않습니다. 변경 전 백업하세요.
5. SQL 자동 실행은 꺼져 있습니다. 예제 데이터가 필요하면 [seed_dummy.sql](sql/seed_dummy.sql)의 선행조건을 확인한 뒤 **개발용 DB에서만** 별도 SQL 클라이언트로 실행하세요.

## 운영(prod)
1. `deploy/crm.env.example`을 서버의 `crm.env`로 복사하고 비밀번호/키를 채우며 `chmod 600` 적용.
2. `crm.env`에 `SPRING_PROFILES_ACTIVE=prod`를 지정합니다. systemd 서비스는 `EnvironmentFile`로 이 파일을 읽습니다.
3. `SERVER_PORT`, `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` 필수. **운영 DB는 스키마가 사전에 준비되어야** 합니다.
4. `ddl-auto=validate`: 기존 스키마를 검사만 하며 생성/변경하지 않습니다. 엔티티와 불일치하면 앱이 시작되지 않습니다.
5. `spring.sql.init.mode=never`: SQL 파일을 통한 예제 INSERT 자동 실행을 차단합니다. 가짜 데이터 생성기는 현재 TODO 스켈레톤이며, 구현 시 개발 환경에서만 실행되도록 제한해야 합니다.
6. 변경 전 DB 백업, 별도 SQL 마이그레이션을 승인·적용한 뒤 배포. 이후 Flyway 도입 권장.

## 목표: 테스트(test)
H2 테스트 의존성은 이미 선언되어 있습니다. 테스트 전용 프로필과 DB 연결 설정을 추가한 후 `@ActiveProfiles("test")`로 실행합니다. 현재 Starter에 테스트용 DB 연결이 자동으로 준비되어 있다고 가정하지 마세요.

## 중요 제한
- 현재 Starter의 SaaS 승인 상태/ADMIN 관리 기능은 공식 설계의 **목표**이며 구현 완료가 아닙니다.
- 주요 화면 Controller와 미리보기 보안 설정은 `@Profile("dev")`이므로 운영에서는 등록되지 않습니다. Thymeleaf 활성화만으로 운영 화면과 인증/인가가 완성되는 것은 아닙니다.
- JDK 25/Boot 4 실제 컴파일·통합 테스트는 별도 환경에서 실행해야 합니다.
- 운영 DB를 빈 상태에서 시작하면 `validate`가 실패하는 것이 정상입니다. 테이블을 먼저 생성/마이그레이션해야 합니다.
