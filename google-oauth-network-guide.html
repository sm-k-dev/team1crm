Chrome Network에서 Google 로그인 요청 확인하기

Spring Boot CRM의 Google 로그인에서 401 invalid_client가 뜰 때, 브라우저가 Google에 전달한 client_id를 확인하는 방법입니다.

HTML 파일 다운로드

  1. 로그인 전에 Network 탭 열기

    Chrome에서 CRM 로그인 화면을 열고 F12 또는 Ctrl + Shift + I를 누릅니다. Network(네트워크) 탭에서 기록이 켜져 있는지 확인하고 Preserve log를 체크합니다. Google로 이동해도 요청 목록이 유지됩니다.

    Clear 버튼으로 이전 요청 목록을 비운 뒤 CRM의 Google 로그인 버튼을 누릅니다.

  2. Google로 이동한 요청 선택하기

    Network 상단에서 All을 선택하고 Filter 칸에 domain:accounts.google.com을 입력합니다. Name 목록에서 auth처럼 보이는 Google 인증 요청을 클릭합니다. Headers → General → Request URL에서 accounts.google.com으로 향하며 URL에 client_id=가 들어 있는 요청을 찾습니다.

    이미 오류 화면이라면 signin/oauth/error 요청에서도 client_id를 확인할 수 있습니다. 처음 Google로 보낸 값을 추적하려면 그보다 앞선 인증 요청을 선택하세요.

  3. Payload에서 client_id 읽기

    Payload → Query String Parameters를 열고 client_id 행을 찾습니다. 같은 위치에서 redirect_uri도 확인할 수 있습니다.

    Headers의 요청 URL에서는 같은 값이 client_id=%24%7BGOOGLE_CLIENT_ID%7D로 표시될 수 있습니다. URL을 디코딩하면 위 예시와 같습니다.

  4. 수정 후 새 요청으로 비교하기

    ${GOOGLE_CLIENT_ID}가 보이면 Spring이 환경변수 참조 문자열을 그대로 보낸 것입니다. IntelliJ의 Run → Edit Configurations → CrmApplication → Environment variables에서 GOOGLE_CLIENT_ID와 GOOGLE_CLIENT_SECRET의 이름 끝에 공백이 없는지 확인합니다.

    서버를 재시작한 뒤 다시 로그인 버튼을 누릅니다. 새 요청의 client_id가 등록된 Google OAuth 클라이언트 ID와 일치하고, 이 CRM의 redirect_uri가 http://localhost:8082/login/oauth2/code/google인지 비교합니다. 로그인 성공 여부는 계정 선택 후 CRM으로 돌아와 로그인 상태가 되는지까지 확인합니다.

목록에 요청이 없거나 화면을 공유할 때
  • 요청이 안 보이면 필터를 지우고 All과 기록 상태를 확인한 뒤 CRM에서 다시 로그인 버튼을 누르세요. 로컬 요청 /oauth2/authorization/google의 Headers → Response Headers → Location에서도 Google로 보낸 URL을 확인할 수 있습니다.
  • 캡처를 공유할 때는 client_id 행만 남기고 이메일 주소, 쿠키, state, 인증 코드, 비밀값은 가리세요.
